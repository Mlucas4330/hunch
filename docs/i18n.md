# Internationalization

> **Where the locale switcher is mounted.** `components/language-toggle.tsx` sits in the navbar
> cluster next to the theme toggle, in the mobile menu, and in the public report's header.
>
> The report is the surface that needs it most, because that route has no navbar: somebody who
> followed a shared link has no other control on the page. Switching there never retranslates what a
> model wrote, which is pinned to `analyses.locale`, so what it changes is the page around it.

Server-side, cookie-driven, **no route segment**. `lib/i18n/`.

**Every user-facing string comes from a dictionary, never inline text.** This is the single rule the
rest of the file elaborates.

## A translation may not assert more than its original

`readout.groups.metadata` read `'What the page tells a machine'` in English and
`'O que a IA precisa está aqui?'` in pt-BR, a question about AI that the English does not ask. `load`
had drifted the same way. Because a group label is read as a claim about every finding under it
([readout.md](readout.md)), **two of the six score bars were making an AI claim in the language real
readers use**, one of them colliding head-on with the AI tab's own question.

That is worse than an awkward phrase. `pt-BR` is a rewrite rather than a translation
([invariants.md](invariants.md)), and the licence that gives is over *wording*, never over what is
being claimed. A rewrite may change the sentence; it may not change the assertion.

It is also the hardest kind of drift to notice: both files typecheck, both read naturally, and nobody
comparing them side by side is looking for a claim that only exists on one side. When editing a label
that governs a group of measurements, read both locales together.


## Mechanics

- Locales are the `LOCALE` enum (`en`, `pt-BR`); `DEFAULT_LOCALE` and `LOCALE_COOKIE` live in
  `lib/constants.ts`. **`DEFAULT_LOCALE` is `pt-BR`**, so a first visit, an unfurl and whatever a
  crawler indexes are all Portuguese. See [seo.md](seo.md#self-canonical-no-hreflang). English is
  reached through the switcher or, as the e2e suite does it, by writing the cookie directly.
  `LOCALE_LABEL` holds the toggle's language names as endonyms, `English` and `Português`, never
  translated in either direction. The switch shows flags and prints neither, so these are its
  accessible names; see [components.md](components.md#language-toggle-componentslanguage-toggletsx).
- `lib/i18n/dictionaries/en.ts` is the **source of truth** and exports the `Dictionary` type;
  `pt-BR.ts` is annotated `: Dictionary`, so a missing key fails `npm run typecheck`.
- `getLocale()` reads `LOCALE_COOKIE` and falls back to `DEFAULT_LOCALE`; `dictionaryFor(locale)`
  returns the matching dictionary.
- **Server components** call `await getDictionary()`, or `dictionaryFor(locale)` when they also need
  the locale itself.
- **Client components** call `useI18n()` from `components/i18n-provider.tsx`, fed by the dictionary
  resolved server-side in each layout.
- The `setLocale` server action (`lib/actions/locale.ts`) writes the cookie and calls
  `revalidatePath('/', 'layout')`.

## Rules for writing entries

- **Dictionaries cross the server -> client boundary**, so entries are plain data, never functions.
- Interpolation uses `{token}` placeholders resolved by `t()` in `lib/i18n/format.ts`; plurals are
  `{ one, other }` objects picked by `t()` from a `count` var.
- Emphasis inside a sentence is marked with `*asterisks*` and rendered by `components/rich-text.tsx`,
  so translators move the bold with the words instead of reassembling JSX.
- **Enum values** (`SECTIONS`, `FLOW_CATEGORY`, `VERDICT`, ...) are Postgres enum values and
  are **never** translated: only their display labels under `dictionary.labels.*` are.
- Dates and numbers go through `formatDate` / `formatDecimal` / `formatNumber` in `lib/i18n/format.ts`,
  so locale formatting never happens ad hoc.

## The blog subtree lives in its own module

`dictionary.blog` is imported into both dictionaries from `en.blog.ts` and `pt-BR.blog.ts` rather
than written inline. Three posts of prose are longer than every other string in the app put together,
and inlining them would bury `landing`, `readout` and `report` in the middle of an essay.

The rule is the same one level down: `en.blog.ts` exports `BlogDictionary`, `pt-BR.blog.ts` is
annotated with it, and a missing key fails `npm run typecheck` exactly as `: Dictionary` makes it. `posts` is typed `Record<BlogSlug, BlogPost>`, so the **enum** decides which posts
exist and neither locale can invent or forget one.

A post's body is data, not markup: `sections` is an array of `{ heading, paragraphs, bullets }` and
`components/blog-article.tsx` renders it. That is why there is no markdown dependency in the project,
and why emphasis inside a post is `*asterisks*` like every other string.

## `pt-BR` is a rewrite, not a translation

The rule itself is in
[invariants.md](invariants.md#pt-br-is-a-rewrite-not-a-translation). Two details worth keeping here,
both learned from real breakage:

- **A technical term the Brazilian market uses in English stays in English.** LCP, meta description,
  alt, CTA, snippet, deploy, landing page, placeholder. Translating those does not make the text
  clearer, it makes it harder to recognize, and the reader works in the field. *"Baixado para abrir a
  página"* for page weight is the shape of the mistake.
- **A rewrite may change the argument, never the thesis, and never the keys.** `pt-BR` is free to
  argue a different way into the same claim, and `landing` does: both locales sell "the document is
  yours and it does not invent", but the English page leads with the deliverable while the Portuguese
  one leads with the invented number. See [analysis-ui.md](analysis-ui.md#landing-page). What it can
  never do is add, drop or rename a key: the `: Dictionary` annotation is the whole safety net, and a
  locale-only key silently defeats it.
- **Accents are not optional.** The whole `metadata` subtree once shipped stripped of them ("analises",
  "voce", "conversao"), which is the browser tab and the link unfurl, so the error is the first thing
  anyone sees. The prompts' typographic rule restricts *punctuation*, never the alphabet, which is
  exactly why it can never be written as "ASCII puro".

## Mail is written in the locale that was stored, never the one that is running

`leads.locale` is pinned when the address is left, exactly as `analyses.locale` is, and the sequence
reads it. This matters more for mail than for a screen: a cron has no reader and no cookie, so
whatever locale the process happens to default to would otherwise decide the language somebody is
written to in.

The one exception is the pending-payment reminder, which goes to a signed-in account. Accounts carry
no locale of their own, so it uses `DEFAULT_LOCALE`, and that is the honest answer rather than a
shortcut: nothing recorded what that person was reading.

## Generated content is not retranslated

See
[invariants.md](invariants.md#generated-content-is-pinned-to-the-locale-it-was-written-in). Switching
language does not retranslate an existing analysis; `current_copy` is the exception because it quotes
the analyzed page verbatim.

## Why the locale is a cookie and not a URL segment

Because `en` and `pt-BR` are genuinely the same URL, each page is its own canonical and claims no
hreflang alternates. See [seo.md](seo.md).
